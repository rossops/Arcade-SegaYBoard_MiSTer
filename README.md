# Sega Y Board for MiSTer FPGA

MiSTer core for Sega's Y Board arcade hardware (Galaxy Force II, Power Drift,
G-LOC, Rail Chase, Strike Fighter). Same approach as the X Board core: simulate
the board, verify every custom chip against a Python port of MAME, then check
whole frames against MAME captures before anything goes near the FPGA.

## Status

Galaxy Force II's attract mode runs with the full video path: the three
68000s, the 315-5305 Y sprites into DDR3, the 315-5306 rotation, the
315-5196 front sprites and the 315-5312 mixer, pixel-exact against MAME's
screenshots, with the Z80 sound board (YM2151 and 315-5218) playing, and
the game plays from the stick (analog or d-pad) with the throttle on two
buttons or an axis. Power Drift, G-LOC Air Battle, G-LOC R360, Rail Chase
and Strike Fighter boot and run their attract modes on the core, Rail
Chase and Strike Fighter pixel-exact against MAME, the others within a
few pixels of animations out of phase by a frame; Power Drift races, G-LOC
and R360 fly and Rail Chase shoots on hardware, Strike Fighter is still to
be played (M7). `docs/DESIGN.md` has the hardware
reference, the architecture and the open questions; `docs/references.md`
says where every file came from.

## Building and testing

- Simulation on macOS: Verilator, Icarus and cocotb in `verif/.venv`
  (`verif/requirements.txt`, Python 3.12). `sh verif/lint.sh` lints every
  module we own. Unit tests: `verif/.venv/bin/python -m pytest verif/unit`.
- The `.rbf` comes from Quartus Prime 17.0 Lite on Windows: `build.bat` on the
  share compiles whatever is checked out and copies a dated `.rbf` to
  `releases/`. Every build gets a hardware test before its `.rbf` is committed.
- `releases/*.mra` are generated by `tools/gen_mra.py` from `tools/romsets.py`
  and never edited by hand; CI diffs them against the generator.
- Releases are semver tags cut by the "Release" workflow (Actions tab or
  `gh workflow run Release -f bump=patch`). Nothing is built or attached; the
  core lives in `releases/`.

## Credits
